# Engine v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the core crate to `fatima-engine` in `crates/engine`, and move the local vault file to format version 2 with the Argon2id, XChaCha20-Poly1305 and X25519 key hierarchy, while every version 1 vault and user key keeps working.

**Architecture:** The v1 crypto and v1 file types move into `vault/legacy/`, kept for reading only. A new `vault/crypto.rs` holds the v2 primitives. `vault/store.rs` writes only version 2 and reads both versions, upgrading a v1 file on its next save while keeping every environment key's bytes.

**Tech Stack:** Rust 2021 workspace; `argon2 0.5`, `chacha20poly1305 0.10`, `crypto_box 0.9` (feature `seal`), `hkdf 0.12`, `sha2 0.10`, alongside the existing `aes-gcm 0.10`, `scrypt 0.11`, `rand 0.8`, `getrandom 0.2` (feature `js`).

**Spec:** `spec.md` (section 1, Engine v2)

## Global Constraints

Copied verbatim from the project's instruction files. Every task obeys all of them.

From `.agents/docs/code.md`:

- **Never create or modify production code before writing the corresponding test.** The test is written first and must fail for the expected reason before the production implementation is changed.
- Crate behaviour is covered from `crates/core/tests/` (after Task 1: `crates/engine/tests/`), against the public API rather than a private function reached through `pub(crate)`. A unit test lives beside its module in a `#[cfg(test)]` block only when the thing under test genuinely has no reachable public surface.
- **Do not write comments in source code. No exceptions.**
- **Never narrate the code or your edits, and never address the reader from inside a file.**
- **Write the minimum amount of code required to solve the problem. Nothing speculative.**
- **Change only what is necessary. Clean up only what your changes affect.**
- Do not keep a deprecated internal function, field, or `pub(crate)` export for compatibility. Delete it.
- When a change does reach one of the four surfaces, that is a decision, not an implementation detail: it belongs in a `spec.md` before it belongs in a diff, and a format that gains a field carries the old files forward rather than rejecting them.
- **No `unwrap()`, no `expect()`, no `panic!` in library or command code.** Return `Result` and let the boundary render it. A test may `unwrap()` freely; nothing that runs for a user may.
- **No `unsafe`.**
- Prefer borrowing to cloning.
- A module is named for what it holds. No `utils.rs`, no `helpers.rs`, no `common.rs`.
- Match the surrounding code's style, naming and idiom.

From `.agents/docs/errors.md`:

- **A failure with a shape gets a variant.** `FatimaError::message("...")` is for the one-off that genuinely carries nothing but a sentence.
- Propagate with `?`. Don't catch a failure only to re-raise it as free text.
- **`miette` stops at the CLI boundary.** Nothing in the engine crate may depend on miette.

From `.agents/docs/runtime.md`:

- **Never reach for `std::fs`, `std::process` or `reqwest` in the engine crate outside a `#[cfg(feature = "native")]` block**, for new code. The vault's existing `std::fs` use in `store.rs` stays as it is in this plan (spec ruling: it moves behind `FatimaHost` in sub-project 3).
- The vault is encrypted at rest, and the vault's crypto modules own that; nothing else reads or writes key material. **A secret never lands in a log, an error message, or a snapshot fixture.** Error variants carry no key material and no plaintext.

From `.agents/docs/done.md`:

- No `#[allow(...)]` on a lint you find inconvenient. `Cargo.lock` is regenerated by cargo, never hand-edited. `static/schema.json` is never hand-edited.

From the spec:

- Argon2id defaults: memory 65536 KiB, 3 iterations, 4 lanes, 32-byte output, salt 16 random bytes.
- HKDF-SHA256 `info` strings, exactly: `fatima/v2/encryption`, `fatima/v2/login`, `fatima/v2/user-key/wrap`, `fatima/v2/user-key/hash`.
- Value associated data, exactly: `fatima/v2/<projectId>/<environment>/<secretId>/<field>` with `field` in `name`, `value`. User secrets use the same string with `user/<userKeyId>/` inserted before `<secretId>`.
- Key-wrapping associated data, exactly: `fatima/v2/<projectId>/account-key`, `fatima/v2/<projectId>/private-key`, `fatima/v2/<projectId>/user-key/<userKeyId>/<environment>`, `fatima/v2/<projectId>/user-environment/<userKeyId>/<environment>`.
- File: `"version": 2`, `"encryption": {"algorithm": "xchacha20-poly1305"}`, `"kdf": {"algorithm": "argon2id", "salt", "memoryKib", "iterations", "parallelism"}`.
- Environment keys keep their bytes across the v1 to v2 upgrade. Only a password session's save upgrades a file; a user-key write of a user secret into a version 1 file uses the v1 encoding and leaves it at version 1.

Implementers never run the typecheck, lint, tests or build (AGENTS.md, `## Subagents`). They write the failing test first, then the code, read their own diff, commit by path following `.agents/skills/core/commit/SKILL.md`, and name the covering test files in their report. The controller runs the gates.

## Review Focus

1. A vault written by the current release (version 1) with secrets in several environments and a user key: opening it with the right password must show every value, and a save must leave a version 2 file the same password opens. Pinned in Task 4.
2. A user key issued before the upgrade, kept in someone's CI: after the file is upgraded, `authenticate_with_user_key` with the same raw key must still read its environments. Pinned in Task 4.
3. The wrong master password on a version 2 file must fail with the wrong-password variant, not a parse error and not a panic. Pinned in Task 3.
4. A ciphertext moved from one secret, environment or field to another inside the file must fail to decrypt with the decrypt variant. Pinned in Task 3.
5. `change_password` on a version 2 vault followed by a save: the old password must fail and the new one must open every value, user keys included. Pinned in Task 3.
